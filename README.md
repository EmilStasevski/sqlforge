# sqlforge: German/English text-to-SQL, QLoRA-tuned on execution-verified synthetic data

sqlforge fine-tunes a 7B code model (Qwen2.5-Coder-7B-Instruct, 4-bit NF4 QLoRA on one 16 GB GPU) to answer
German and English questions with DuckDB SQL. **Every training label is checked by running it.** Nothing in
the dataset was labelled or checked by hand. The model is evaluated by **execution accuracy** on a database
schema it never saw during training, and it is served through a Go gateway with a Redis cache. Request events
flow through Kafka into ClickHouse and Grafana.

```
schemas (TPC-H, SMARD via dbt, Open-Meteo) ─► grammar-based SQL sampler ─► DuckDB execution verifier
      ─► DE/EN question templates ─► local-LLM paraphrase (Ollama) + preservation filter ─► Pandera ─► DVC/MinIO
      ─► QLoRA (TRL + PEFT + bitsandbytes; MLflow + W&B) ─► eval (execution accuracy, buckets, error taxonomy)
      ─► merge ─► GGUF Q4_K_M ─► Ollama

client ─► Go gateway :8080 ── Redis (exact + normalized-question cache, rate limit), Prometheus /metrics
             │                └─ Kafka ask.events ─► consumer ─► ClickHouse ─► Grafana
             ▼
        FastAPI executor :8000 ─► model server (Ollama, GGUF) ─► Rust sqlnorm guard ─► DuckDB (read-only)
```

## How the data is made (and why no manual check is needed)

| Step | What guarantees correctness |
|---|---|
| Schemas | TPC-H (generated by DuckDB), SMARD electricity data (dbt marts, 20 dbt tests), Open-Meteo weather for 6 NRW cities (**held out**: test only) |
| SQL | Sampled from a typed grammar (12 query kinds: filters, aggregates, GROUP BY/HAVING, top-k, joins via FK paths, subqueries, time buckets). Literals are drawn from the real data |
| Verification | A query is kept only if it is a single read-only SELECT (Rust `sqlnorm`), runs within the timeout, returns 1–10 000 rows that are not all NULL, gives the same result single- and multi-threaded, has no ties at its ORDER BY/LIMIT boundary, and returns the same result under the renamed/subset training schema |
| Questions | Rendered from the same spec as the SQL (DE + EN). A paraphrase (qwen3:8b) replaces the template only if it keeps every literal, glossary term, number and operator concept ("average", "greater than", "not", …) and stays in the same language |
| Splits | Canonical-SQL hash dedup and a leak check across splits; Pandera contract on every split; build is deterministic (verified by rebuild) |
| Augmentation | Random table/column subsets, shuffled order and renamed identifiers (23 % of train), so the model reads the DDL instead of memorising TPC-H |

## Quickstart

```bash
uv sync --group train          # Python 3.12, torch cu128 (Blackwell OK), builds the Rust extension
make env-check                 # toolchains, GPU, databases
make data                      # dvc repro: schemas -> verified dataset -> paraphrases (needs Ollama)
make eval-baseline             # base model zero-/few-shot
make train                     # QLoRA, 1 epoch
make eval-qlora gguf           # evaluate adapter; merge -> GGUF Q4_K_M
make up                        # gateway, executor, Ollama, Redis, Kafka, ClickHouse, Grafana, MinIO, MLflow, Prometheus
curl -s localhost:8080/ask -d '{"question":"Wie viele Tage mit mehr als 20 mm Niederschlag gab es 2024 in Köln?","db":"weather"}'
make loadtest                  # vegeta, Redis cache on vs off
make test bench                # pytest + sqlnorm vs sqlglot benchmark
```

Grafana: http://localhost:3000 (dashboard "sqlforge serving"). MLflow: `uv run mlflow ui --backend-store-uri sqlite:///mlflow.db`.

## Kurzfassung (DE)

sqlforge erzeugt Text-to-SQL-Trainingsdaten (Deutsch/Englisch) vollautomatisch: SQL wird aus einer Grammatik
gesampelt, auf DuckDB ausgeführt und nur behalten, wenn alle automatischen Prüfungen bestehen; Fragen werden aus
derselben Spezifikation erzeugt und per lokalem LLM paraphrasiert, wobei ein Filter Werte, Fachbegriffe und
Operatoren absichert. Ein 7B-Modell wird per QLoRA auf einer 16-GB-GPU feinjustiert und nach Ausführungsgenauigkeit
auf einem ungesehenen Schema (Wetterdaten NRW) bewertet. Serving über Go-Gateway mit Redis-Cache, Kafka-Events nach
ClickHouse und ein Grafana-Dashboard.
